Wofür wird ein API Gateway bei Microservice Architekturen benötigt und welche Vorteile ergeben sich durch seine Verwendung? Inwiefern unterscheidet sich ein API Gateway zu einem API Proxy?

In einer Microservice-Architektur kann es eine große Anzahl von verteil- ten Diensten geben, die untereinander kommunizieren müssen. Um diese Kommu- nikation zu vereinfachen und zu organisieren, kann ein API-Gateway eingesetzt werden.

Ein API-Gateway ist eine Komponente, die als Vermittler zwischen Clients und den einzelnen Microservices agiert. Es bietet eine zentrale Schnittstelle für externe Clients und bündelt mehrere APIs, die von unterschiedlichen Services bereitgestellt werden. Das Gateway kann auch verschiedene Funktionen ausführen, wie Authen- tifizierung, Autorisierung, Lastenausgleich, Caching und Protokollierung. Einige der Vorteile, die sich durch die Verwendung eines API-Gateways ergeben, sind:

  • Zentrale Schnittstelle: Das API-Gateway bietet eine zentrale Schnittstelle für externe Clients, die auf mehrere Microservices zugreifen möchten. Dadurch wird die Komplexität der Client-Server-Kommunikation reduziert.
  • Erhöhte Sicherheit: Das API-Gateway kann Authentifizierung und Autorisierung durchführen, bevor die Anfrage an den entsprechenden Microservice weit- ergeleitet wird. Dadurch wird die Sicherheit erhöht und unbefugte Zugriffe auf die Microservices werden verhindert.
  • Skalierbarkeit: Das API-Gateway kann auch als Load Balancer fungieren, indem es Anfragen an verschiedene Instanzen der Microservices weiterleitet. Dadurch können Engpässe vermieden werden, und die Skalierbarkeit wird verbessert.

Ein API-Proxy ist eine ähnliche Komponente wie das API-Gateway, die auch als Vermittler zwischen Clients und den einzelnen Services agiert. Der Hauptunter- schied zwischen einem API-Gateway und einem API-Proxy besteht darin, dass das API-Gateway zusätzliche Funktionen bietet, wie z.B. Authentifizierung, Au- torisierung, Lastenausgleich, Caching und Protokollierung. Ein API-Proxy dient hingegen hauptsächlich als Weiterleitung von Anfragen an den entsprechenden Ser- vice und bietet keine zusätzlichen Funktionen.

Nennen Sie Dinge die durch die Implementierung eines Fat Clients ermöglicht werden. Welche Nachteile könnte die Verwendung eines Fat Clients nach sich ziehen?

Ein Fat Client ist eine Anwendungsarchitektur, bei der die meisten oder alle Verarbeitungs- und Datenmanipulationsaufgaben auf dem Client ausgeführt werden, während der Server hauptsächlich als Datenbank- und Speicherungsquelle dient. Einige Dinge, die durch die Implementierung eines Fat Clients ermöglicht werden, sind:

  • Bessere Benutzererfahrung: Durch die Verarbeitung von Daten und Geschäft- slogik auf dem Client kann eine reaktionsschnelle und schnell ladende Be- nutzeroberfläche bereitgestellt werden, was zu einer besseren Benutzererfahrung führt
  • Offline-Verfügbarkeit: Da der Fat Client die meisten oder alle Verarbeitungs- und Datenmanipulationsaufgaben auf dem Client ausführt, kann die Anwen- dung auch ohne Internetverbindung ausgeführt werden, was in einigen Fällen sehr nützlich sein kann.
  • Weniger Netzwerkverkehr: Durch die Verarbeitung von Daten auf dem Client kann der Netzwerkverkehr reduziert werden, da weniger Daten zwischen Client und Server übertragen werden müssen.

Recherchieren Sie den Lifecycle eines Java Servlets. Wird für jede Anfrage ein neues Servlet initialisiert? Nennen Sie Beispiele für Servlet Container. Warum wird dieser benötigt?

Nein, es wird nicht jedes Mal ein neues Servlet initialisiert. Der Servlet- Container erstellt normalerweise nur eine einzige Instanz des Servlets und ver- wendet diese für alle eingehenden Anfragen. Jede Anfrage wird dann von einem separaten Thread des Servlet-Containers verarbeitet. Einige Beispiele für Servlet-Container sind: 1. Apache Tomcat 2. Jetty 3. IBM WebSphere Application Server 4. Oracle WebLogic Server 5. Red Hat JBoss Enterprise Application Platform Der Servlet-Container ist eine wichtige Komponente in der Java-Webentwicklung, da er das Lebenszyklusmanagement von Servlets übernimmt. Der Container ini- tialisiert das Servlet beim Start der Anwendung, ruft die Methode init() auf, um das Servlet zu initialisieren, und ruft die Methode service() auf, um jede eingehende Anfrage zu verarbeiten. Der Servlet-Container sorgt auch dafür, dass das Servlet ordnungsgemäß beendet wird, indem er die Methode destroy() aufruft, wenn die Anwendung gestoppt wird. Darüber hinaus bietet der Servlet-Container auch Funktionen wie Sitzungsver- waltung, Sicherheit, Ressourcenverwaltung und Lastenausgleich. Er ist somit ein wichtiger Bestandteil von Java-Webanwendungen und trägt zur effizienten und zu- verlässigen Ausführung von Servlets bei.
