Fast URL spam / ads / security-risk classifier

Master's thesis or compact project thesis

Build a URL-only classifier that learns from existing spam, ads, and security-risk URLs, then scores new URLs with a very small inference cost.

URL-onlyfast inferencegeneralises wellsecurity risk

Why this fits

  • URL strings carry strong lexical and structural cues, so the model can stay lightweight.
  • Character n-grams and hashed features usually generalise better than hand-written domain rules.
  • A linear model can be exported compactly and evaluated in microseconds per URL.

Suggested approach

  • Collect positive examples from existing spam, ad, and security-risk URL sets, then balance them with benign URLs.
  • Train a compact character n-gram model, such as hashed logistic regression or a linear SVM with calibration.
  • Validate on held-out domains and path patterns to measure generalisation, not just memorisation.

Target output: Binary risk score plus probability estimate for fast filtering, triage, or pre-screening.

OURRS ranking profiles with lightweight client-side XGBoost re-ranking

Master's thesis or research prototype

Design profile-based ranking for the OURRS search engine, where clients submit compact XGBoost parameter profiles with the query and the server re-ranks against the requested profile.

rankingOURRSXGBoostprofiles

Why this fits

  • Different ranking profiles can surface meaningfully different result orders without changing the underlying index.
  • Client-side profile selection keeps the system flexible while preserving a fast server-side ranking path.
  • Discovering a set of diverse profiles is naturally an unsupervised problem about coverage, separation, and ranking diversity.

Suggested approach

  • Define a small set of feature and parameter profiles for XGBoost learning-to-rank, with each profile tuned for a distinct ranking bias.
  • On the server, search for 20 to 30 profiles that maximize ranking differences on average queries while staying stable and explainable.
  • Assign human-readable names to the resulting profiles so clients can request them directly alongside the search request.

Target output: A named profile family, client-requestable ranking configuration, and a diversity-oriented profile discovery method.

Large-scale hierarchical multilabel classification for OpenWebIndex categories

Master's thesis

Build a large-scale hierarchical classification dataset for OpenWebIndex pages based on the Curlie category hierarchy, then develop and evaluate a fast multilabel classifier using Jina v5 embeddings against TF-IDF and BM25-based baselines.

OpenWebIndexCurlie hierarchymultilabelJina v5

Why this fits

  • The current category assignment is rule-based, so there is a clear opportunity to build a stronger data-driven classifier.
  • The Curlie taxonomy introduces a realistic hierarchical label space rather than a flat single-label benchmark.
  • The comparison between embedding-based and lexical retrieval-style methods is practically important because TF-IDF or BM25 classifiers may be much cheaper and faster at scale.

Suggested approach

  • Construct a large-scale training and evaluation dataset from OpenWebIndex pages and Curlie-aligned category signals, with careful handling of hierarchy, multilabel assignments, and noisy labels.
  • Use Jina v5 embeddings to build a fast multilabel classifier, for example with nearest-neighbour, centroid-based, or lightweight linear classification layers on top of embeddings.
  • Benchmark against TF-IDF and BM25-style lexical baselines with attention to both effectiveness and system cost, including throughput, latency, memory, and indexing complexity.

Target output: A reusable hierarchical multilabel dataset, an embedding-based classifier, strong lexical baselines, and a clear effectiveness-versus-efficiency comparison for large-scale category assignment.

Interesting topics

Multi-objective alignment for fine-tuning

Study how fine-tuning can optimize several alignment goals at once, such as helpfulness, factuality, safety, style control, and task success, without collapsing into one dominant objective.

Why it is interesting

  • Model tradeoffs between partially conflicting objectives instead of treating alignment as a single scalar target.
  • Compare weighting, constrained optimization, Pareto-front exploration, and post-hoc selection of aligned model variants.
  • Design evaluation setups that make alignment tradeoffs measurable and actionable for real deployment decisions.

APIs for AI agent control

Design and evaluate API patterns for controlling AI agents: permissions, interruption, tool routing, delegation, observability, and safe state transitions.

Why it is interesting

  • Define control primitives for pausing, resuming, redirecting, or constraining long-running agent workflows.
  • Study how API design affects reliability, user trust, and safe recovery from bad tool choices or runaway plans.
  • Compare thin command APIs against richer protocol-style agent interfaces with explicit control and feedback loops.
